# FlowDesk API Specification

This document details the cross-cutting patterns, authentication conventions, error handling mechanisms, and routing guidelines for the FlowDesk API. 

## Live API Documentation
The live Swagger/OpenAPI interactive endpoint reference is served at [/swagger](http://localhost:5000/swagger) (or `/swagger/index.html` on the API host). This document covers the systemic API behaviors and design conventions that Swagger does not detail on its own.

---

## Authentication
Authentication is configured in [Program.cs](file:///c:/Users/Admin/Desktop/FlowDesk/src/FlowDesk.Api/Program.cs#L73) and [AuthExtension.cs](file:///c:/Users/Admin/Desktop/FlowDesk/src/FlowDesk.Infrastructure/Identity/Extensions/AuthExtension.cs) using standard JWT Bearer tokens.

### Obtaining a Token
Authentication tokens are issued by [AuthServices.cs](file:///c:/Users/Admin/Desktop/FlowDesk/src/FlowDesk.Infrastructure/Identity/Services/AuthServices.cs#L107) under the `/api/auth` prefix:
*   **User Registration**: `POST /api/auth/register` (returns user context and tokens)
*   **User Login**: `POST /api/auth/login` (returns user context and tokens)
*   **Token Refresh**: `POST /api/auth/refresh` (exchanges a valid, non-expired refresh token for new access and refresh tokens)

### Claims
JWT access tokens generated by [JwtTokenGenerator.cs](file:///c:/Users/Admin/Desktop/FlowDesk/src/FlowDesk.Infrastructure/Identity/Services/JwtTokenGenerator.cs#L28) contain the following claims:
*   `http://schemas.xmlsoap.org/ws/2005/05/identity/claims/nameidentifier`: The unique user identifier (as a `Guid`).
*   `http://schemas.xmlsoap.org/ws/2005/05/identity/claims/emailaddress`: The user's registered email address.
*   `http://schemas.xmlsoap.org/ws/2005/05/identity/claims/name`: The user's username.
*   `is_system_admin`: Populated with `"true"` if the user has system administrator privileges.

### Refresh Token Flow
*   **Rotation**: Refresh tokens are cryptographically secure random base64 strings generated via [JwtTokenGenerator.cs](file:///c:/Users/Admin/Desktop/FlowDesk/src/FlowDesk.Infrastructure/Identity/Services/JwtTokenGenerator.cs#L60). Their SHA256 hashes are persisted in the database.
*   **Token Reuse Protection**: If a refresh token is reused (indicating a potential breach), the API invalidates and revokes all active refresh tokens for the associated user immediately.
*   **Validity**: By default, access tokens expire in 15 minutes and refresh tokens expire in 7 days (defined in [appsettings.json](file:///c:/Users/Admin/Desktop/FlowDesk/src/FlowDesk.Api/appsettings.json#L19-L20)).

## Error Response Format
When a request fails, the global [ExceptionMiddleware.cs](file:///c:/Users/Admin/Desktop/FlowDesk/src/FlowDesk.Api/Middleware/ExceptionMiddleware.cs) captures the error and serializes a flat, camelCase JSON response mapping to the [ErrorResponse](file:///c:/Users/Admin/Desktop/FlowDesk/src/FlowDesk.Api/Middleware/ExceptionMiddleware.cs#L104) record:

*   `error`: A machine-readable string indicating the category/code of the error (e.g. `"ValidationError"`, `"NotFound"`).
*   `message`: A human-readable message summarizing the failure.
*   `details`: Optional structured context containing additional error details (e.g., validation rules broken, or `null` if none).

### Example 1: Standard Error (404 Not Found)
Returned when a requested resource does not exist in the database:
```json
{
  "error": "NotFound",
  "message": "Asset with id 3fa85f64-5717-4562-b3fc-2c963f66afa6 was not found.",
  "details": null
}
```

### Example 2: Validation Error (400 Bad Request)
Returned when request parameters fail FluentValidation. The `details` field contains a camelCase key-value dictionary where keys are the invalid request property names, and values are arrays of string error messages:
```json
{
  "error": "ValidationError",
  "message": "One or more validation errors occurred.",
  "details": {
    "name": [
      "Asset name is required."
    ],
    "categoryId": [
      "Category ID must be valid."
    ],
    "manufacturer": [
      "'Manufacturer' must not be empty."
    ]
  }
}
```

## Status Code Conventions
Exceptions mapping to HTTP status codes are defined explicitly inside the switch expression in [ExceptionMiddleware.cs](file:///c:/Users/Admin/Desktop/FlowDesk/src/FlowDesk.Api/Middleware/ExceptionMiddleware.cs#L48):

| Exception Type | Scenario | Status Code | Why / Notes |
| :--- | :--- | :--- | :--- |
| `ValidationException` | Input properties fail FluentValidation rules. | `400 Bad Request` | Returns `"ValidationError"`. The `details` property carries a camelCase dictionary of property errors. |
| `DomainException` | Request violates business logic constraints in core domain models. | `400 Bad Request` | Returns `"DomainError"` with the domain-specific message. |
| `IdentityException` | ASP.NET Core Identity authentication or registration operation fails. | `400 Bad Request` | Returns `"IdentityError"` with details listing specific Identity framework failures. |
| `UnauthorizedAccessException` | Request is unauthenticated, or the JWT token signature/expiry is invalid. | `401 Unauthorized` | Returns `"Unauthorized"`. |
| `ForbiddenException` | The user is authenticated but is not a member of the workspace or lacks the required role/permission. | `403 Forbidden` | Returns `"Forbidden"`. |
| `NotFoundException` | The requested database entity (workspace, ticket, asset, etc.) does not exist. | `404 NotFound` | Returns `"NotFound"`. |
| `DomainStateException` | An action attempts an invalid lifecycle state transition. | `409 Conflict` | Returns `"InvalidStateTransition"`. |
| `ConflictException` | Standard resource concurrency mismatch or unique database constraint violation. | `409 Conflict` | Returns `"Conflict"`. |
| `PermissionMethodNotFoundException` | A checked security permission has no corresponding evaluation method. | `500 Internal Server Error` | Considered a developer/config error. Returns `"InternalError"`. |
| `Exception` (unhandled) | Any unanticipated server exception. | `500 Internal Server Error` | Logged to the server console and rolls back transactions. Returns generic `"InternalError"`. |

## Common Conventions

### Routing
FlowDesk follows a RESTful route design:
*   **Workspace Resource Isolation**: APIs targeting specific workspace resources include the workspace context directly in the route parameter prefix: `/api/workspaces/{workspaceId}/tickets` and `/api/workspaces/{workspaceId}/assets`.
*   **Global Actions**: Auth operations are routed under `/api/auth/[action]`. System administrative commands are routed under `/api/systemadmin/[action]`.
*   **Controller Setup**: Secure endpoints consistently utilize primary constructors to inject MediatR's `IMediator` and are decorated with `[Authorize]`, `[ApiController]`, and `[Route]`. Endpoints do not implement API versioning.

### Headers
*   **Authorization**: Every protected endpoint requires the `Authorization` header containing the Bearer token scheme:
    ```http
    Authorization: Bearer <token>
    ```
*   **Content-Type**: Server error, request, and success responses default to `application/json`.

### Pagination & Sorting
List-based endpoints (such as `ListAssets` and `ListTickets`) inherit pagination parameters from the [QueryParameters](file:///c:/Users/Admin/Desktop/FlowDesk/src/FlowDesk.Application/Common/Pagination/QueryParameters.cs#L3) record:
*   `page`: The page index to fetch (default: `1`).
*   `pageSize`: The maximum number of records to return (default: `20`).
*   `sortBy`: The name of the field to sort by (optional).
*   `descending`: Sort direction boolean (default: `false`).

Response envelopes return a standard flat [PagedResult](file:///c:/Users/Admin/Desktop/FlowDesk/src/FlowDesk.Application/Common/Pagination/PagedResult.cs#L3) envelope:
```json
{
  "items": [],
  "page": 1,
  "pageSize": 20,
  "totalCount": 0,
  "totalPages": 0,
  "hasNextPage": false,
  "hasPreviousPage": false
}
```

## Permission / Authorization Architecture

Access control relies on middleware extraction combined with a MediatR pipeline validation chain:

1.  **Context Loading**: On every incoming request, the [CurrentUserMiddleware.cs](file:///c:/Users/Admin/Desktop/FlowDesk/src/FlowDesk.Infrastructure/Identity/Middleware/CurrentUserMiddleware.cs) extracts claims from the security context and configures a scoped `ICurrentUserContext`.
2.  **MediatR Behaviors Pipeline**:
    *   **System Admin Scope**: Requests implementing `ISystemAdminRequest` pass through [SystemAdminBehaviour.cs](file:///c:/Users/Admin/Desktop/FlowDesk/src/FlowDesk.Application/Behaviours/SystemAdminBehaviour.cs) to confirm that the user has the system administrator claim.
    *   **Workspace Membership Verification**: Requests implementing `IWorkspaceRequest` flow through [AuthorizationBehaviour.cs](file:///c:/Users/Admin/Desktop/FlowDesk/src/FlowDesk.Application/Behaviours/AuthorizationBehaviour.cs), which checks if the authenticated user is a member of the workspace specified by `workspaceId`. If member check fails, it throws a `ForbiddenException`. On success, it populates the `ICurrentWorkspaceContext` with the user's role.
    *   **Feature-Specific Permissions**: Requests requiring specific rights are marked with `[RequirePermission(Permissions.xxx)]` and verified in [PermissionBehaviour.cs](file:///c:/Users/Admin/Desktop/FlowDesk/src/FlowDesk.Application/Behaviours/PermissionBehaviour.cs#L8) by evaluating the active workspace context against allowed roles.
