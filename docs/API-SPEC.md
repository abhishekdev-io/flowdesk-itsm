# FlowDesk API Specification

This document details the cross-cutting patterns, authentication conventions, error handling mechanisms, real-time WebSocket contracts, and routing guidelines for the FlowDesk API.

## Live API Documentation
The live Swagger/OpenAPI interactive endpoint reference is served at [/swagger](http://localhost:5030/swagger) in `Development` mode (or on port `8080` in containerized environments). This document details systemic API behaviors, security lifecycles, and architectural conventions that Swagger does not cover on its own.

---

## API Versioning & Routing

FlowDesk adheres to URL segment API versioning powered by `Asp.Versioning.Mvc`:
* **Base Route Pattern**: `/api/v{version:apiVersion}/[controller]` (e.g., `/api/v1/workspaces`).
* **Current Version**: `1.0` (v1).
* **Workspace Resource Isolation**: Sub-resources belonging to a workspace include the tenant identifier in their route:
  - `/api/v1/workspaces/{workspaceId}/tickets`
  - `/api/v1/workspaces/{workspaceId}/assets`
  - `/api/v1/workspaces/{workspaceId}/notifications`
* **Global & Identity Actions**: Authentication is routed under `/api/v1/auth/[action]`. System administrator endpoints are routed under `/api/v1/systemadmin/[action]`.

## Authentication & Session Lifecycle

Authentication is built with ASP.NET Core Identity and JWT Bearer tokens configured in [AuthExtension.cs](file:///c:/Users/Admin/Desktop/FlowDesk/src/FlowDesk.Infrastructure/Identity/Extensions/AuthExtension.cs) and [AuthController.cs](file:///c:/Users/Admin/Desktop/FlowDesk/src/FlowDesk.Api/Controllers/AuthController.cs).

### Token Architecture
FlowDesk employs a split-token security model to prevent cross-site scripting (XSS) and token theft:
1. **Access Token (Short-Lived)**: A stateless, cryptographically signed JWT with a 15-minute expiration stored exclusively in client application memory.
2. **Refresh Token (Long-Lived)**: A cryptographically secure random 64-byte string with a 7-day expiration, persisted in the database as an SHA-256 hash and delivered to the browser exclusively inside an `HttpOnly`, `Secure`, `SameSite` cookie.

```mermaid

    autonumber
    actor Client as Browser (React SPA)
    participant Nginx as Reverse Proxy (Nginx)

```

### Endpoints

| Method | Endpoint | Description | Auth Required | Refresh Token Delivery |
| :--- | :--- | :--- | :---: | :--- |
| `POST` | `/api/v1/auth/register` | Registers a new user account and seeds personal context. | No | Issued in `HttpOnly` cookie. |
| `POST` | `/api/v1/auth/login` | Authenticates email/password credentials. | No | Issued in `HttpOnly` cookie. |
| `POST` | `/api/v1/auth/refresh-token` | Rotates the refresh token and issues a new access token. | Cookie | Read from cookie; new token set in cookie. |
| `POST` | `/api/v1/auth/logout` | Revokes the current session and clears the cookie. | No | Clears cookie (`Expires = Unix epoch`). |

### JWT Claims
Access tokens generated by [JwtTokenGenerator.cs](file:///c:/Users/Admin/Desktop/FlowDesk/src/FlowDesk.Infrastructure/Identity/Services/JwtTokenGenerator.cs) embed the following claims:
* `http://schemas.xmlsoap.org/ws/2005/05/identity/claims/nameidentifier`: Unique User ID (`Guid`).
* `http://schemas.xmlsoap.org/ws/2005/05/identity/claims/emailaddress`: User email address.
* `http://schemas.xmlsoap.org/ws/2005/05/identity/claims/name`: Username.
* `is_system_admin`: `"true"` if user has platform-wide superadmin privileges; omitted otherwise.

### Cookie Configuration
The refresh token cookie is configured via `RefreshTokenCookieSettings`:
```csharp
Response.Cookies.Append("refreshToken", token, new CookieOptions
{
    HttpOnly = true,                                     // Inaccessible to document.cookie (XSS immune)
    Secure = true,                                       // Transmitted exclusively over TLS/HTTPS
    SameSite = SameSiteMode.None,                        // Configured to support cross-origin SPA setups
    Path = "/api/v1/auth",                               // Scoped strictly to authentication endpoints
    Expires = DateTimeOffset.UtcNow.AddDays(7)
});
```

### Token Rotation & Breach Detection
* **Family Rotation**: Every call to `POST /api/v1/auth/refresh-token` revokes the incoming refresh token and issues a new one. The old token stores a reference to `ReplacedByTokenId`.
* **Breach Invalidation**: If an already-revoked refresh token is presented (indicating that a malicious actor has captured and attempted to replay an old token), the system flags the breach and immediately revokes all active refresh tokens belonging to that user.

## Real-Time Notifications (SignalR WebSockets)

FlowDesk provides bidirectional real-time event broadcasting powered by ASP.NET Core SignalR.

### Hub Endpoint & Handshake

* **Endpoint**: `/api/v1/hubs/notifications`
* **Transport**: WebSockets (with fallback to Server-Sent Events / Long Polling).
* **Handshake Authentication**: Because browser WebSocket clients cannot send standard custom `Authorization: Bearer` headers during the HTTP upgrade handshake, the access token is passed as a query string parameter:
  ```http
  GET /api/v1/hubs/notifications?access_token=<JWT>&workspaceId=<WORKSPACE_GUID> HTTP/1.1
  Connection: Upgrade
  Upgrade: websocket
  ```
  The server intercepts this in [AuthExtension.cs](file:///c:/Users/Admin/Desktop/FlowDesk/src/FlowDesk.Infrastructure/Identity/Extensions/AuthExtension.cs) via `JwtBearerEvents.OnMessageReceived` and binds the JWT to the connection context.

### Multi-Tenant Authorization & Group Routing
When a connection is established, [NotificationHub.cs](file:///c:/Users/Admin/Desktop/FlowDesk/src/FlowDesk.Api/Hubs/NotificationHub.cs) validates the user and workspace:
1. Validates that the caller is an active member of the requested `workspaceId` via `IMembershipChecker`. Unauthorized connections are immediately aborted via `Context.Abort()`.
2. Adds the socket connection to a strictly partitioned group:
   ```csharp
   var groupName = $"workspace:{workspaceId}:user:{userId}";
   await Groups.AddToGroupAsync(Context.ConnectionId, groupName);
   ```
3. Side effects (e.g., ticket assignments, status updates, mentions) invoke `IRealtimeNotificationPublisher.SendToUserAsync`, which targets only the recipient's isolated workspace group.

### Hub Events
The server emits the following client event over the active socket:

#### `NotificationReceived`
Dispatched whenever an activity triggers an alert for the connected user.
```json

}
```

## Health Checks & Diagnostics

FlowDesk exposes standardized ASP.NET Core Health Check endpoints used by container orchestrators and reverse proxies:

| Endpoint | Probe Type | Description | Expected Status |
| :--- | :--- | :--- | :---: |
| `GET /health/live` | Liveness | Verifies that the Kestrel web server process is responsive. | `200 OK` |
| `GET /health/ready` | Readiness | Verifies that PostgreSQL database connectivity and migrations are healthy. | `200 OK` |

In Docker Compose, the API service relies on `/health/ready` for container startup ordering and dependency synchronization.

## Standard Error Response Format

Errors are captured by [ExceptionMiddleware.cs](file:///c:/Users/Admin/Desktop/FlowDesk/src/FlowDesk.Api/Middleware/ExceptionMiddleware.cs) and serialized into a uniform, camelCase response envelope:

```json
{
  "error": "ValidationError",
  "message": "One or more validation errors occurred.",
  "details": {
    "title": [
      "Ticket title is required."
    ],
    "priority": [
      "Priority value must be a valid enum."
    ]
  }
}
```

### Status Code Mappings

| Exception Type | HTTP Status | Error Code | Description / Context |
| :--- | :---: | :--- | :--- |
| `ValidationException` | `400 Bad Request` | `"ValidationError"` | FluentValidation rules failed. Field-level errors listed in `details`. |
| `DomainException` | `400 Bad Request` | `"DomainError"` | Core domain business invariants violated. |
| `IdentityException` | `400 Bad Request` | `"IdentityError"` | ASP.NET Core Identity validation failed (e.g. password policy). |
| `UnauthorizedAccessException` | `401 Unauthorized` | `"Unauthorized"` | Missing or expired JWT access token. |
| `ForbiddenException` | `403 Forbidden` | `"Forbidden"` | Insufficient workspace permissions or inactive membership. |
| `NotFoundException` | `404 Not Found` | `"NotFound"` | The requested entity (workspace, ticket, asset, etc.) does not exist. |
| `DomainStateException` | `409 Conflict` | `"InvalidStateTransition"` | Illegal ticket or asset lifecycle state transition attempted. |
| `ConflictException` | `409 Conflict` | `"Conflict"` | Concurrency conflict (`xmin` mismatch) or unique constraint collision. |
| `Exception` (unhandled) | `500 Internal Error`| `"InternalError"` | Unexpected server-side failure. Full stack trace logged to Serilog. |

## Pagination & Filtering Conventions

List endpoints accept standardized query parameters and return paged envelopes:

### Request Query Parameters
* `page`: 1-based page index (default: `1`).
* `pageSize`: Number of records per page (default: `20`, max: `100`).
* `sortBy`: Name of the field to order by (e.g., `"createdAt"`, `"priority"`).
* `descending`: Boolean indicating sort direction (default: `false`).
* `search`: Optional string filter for title/text matches.

### Response Envelope (`PagedResult<T>`)
```json
{
  "items": [],
  "page": 1,
  "pageSize": 20,
  "totalCount": 85,
  "totalPages": 5,
  "hasNextPage": true,
  "hasPreviousPage": false
}
```
